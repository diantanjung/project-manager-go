Struktur Project Go

Struktur project ini mengikuti pola umum aplikasi Go: entry point di cmd, kode internal di internal, dan migrasi database di migrations.

Pohon folder utama

cmd/
  db/        command migrasi, ping database, seed
  server/    entry point HTTP server
internal/
  auth/      JWT dan hash refresh token
  config/    env dan konfigurasi aplikasi
  domain/    model bisnis dan error domain
  httpapi/   router, middleware, handler, response
  service/   business logic dan authorization workflow
  store/
    postgres/ implementasi persistence PostgreSQL
migrations/   SQL migration naik dan turun
doc/          catatan dan tutorial

Kenapa ada cmd?

Folder cmd berisi program yang bisa dijalankan. Project ini punya dua program:

  • cmd/server: menjalankan HTTP API.
  • cmd/db: menjalankan tugas database seperti migrasi dan seed.

Prinsip Go yang dipakai: file main.go di cmd sebaiknya tipis. Ia cukup membaca config, menyusun dependency, lalu memanggil layer lain.

Kenapa ada internal?

internal adalah fitur Go. Package di dalam folder ini hanya bisa di-import oleh kode yang berada di dalam tree module yang sama. Ini cocok untuk aplikasi backend karena package seperti service, httpapi, dan postgres bukan library publik.

Layer project

Layer Tanggung jawab Tidak seharusnya
domain Menyimpan tipe inti: user, team, project, task, enum, pagination, error. Membuka HTTP request atau query database.
service Validasi bisnis, role check, orchestrasi workflow. Mengikat diri ke Gin atau sqlx secara langsung.
httpapi Routing, parsing request, middleware, response. Menaruh query SQL atau logic bisnis berat.
store/postgres Implementasi database PostgreSQL. Mengatur role HTTP atau membaca header.

Dependency direction

Layer luar boleh memakai layer dalam, tetapi layer dalam sebaiknya tidak tahu detail layer luar.

cmd/server
  imports config, auth, service, postgres, httpapi

httpapi
  imports service dan domain

service
  imports domain dan auth

postgres
  imports domain dan service untuk tipe input/filter interface
Ide penting: service tidak bergantung ke postgres.Store secara konkret. Service hanya butuh interface Store. Ini yang membuat test service bisa memakai fake store.

Tahapan pembuatan versi sederhana

  1. Buat go.mod.
  2. Buat model domain seperti User, Project, Task.
  3. Buat service dengan interface store.
  4. Buat implementasi store PostgreSQL.
  5. Buat router dan handler HTTP.
  6. Wire semuanya di cmd/server/main.go.
  7. Tambahkan migrasi dan test.
