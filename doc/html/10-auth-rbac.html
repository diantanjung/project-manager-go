Authentication dan RBAC

Auth menjawab "siapa user ini?". RBAC menjawab "apakah user ini boleh melakukan aksi ini?". Project ini memakai JWT, refresh token, bcrypt, middleware, dan role check.

Login flow

  1. Handler membaca email dan password.
  2. Service mencari user berdasarkan email.
  3. Password dibandingkan dengan hash bcrypt.
  4. Service membuat access token dan refresh token.
  5. Refresh token di-hash lalu disimpan ke database.
  6. Response mengirim user, access token, dan cookie refresh token.
if bcrypt.CompareHashAndPassword([]byte(user.PasswordHash), []byte(input.Password)) != nil {
    return AuthResult{}, domain.NewError(domain.ErrInvalidCredential, "Invalid credentials")
}

Access token dan refresh token

Token Fungsi Umur default
Access token Dikirim di header Authorization untuk request API. 15m
Refresh token Dipakai untuk mendapat access token baru. 7d

Middleware auth

Middleware memeriksa header:

Authorization: Bearer <accessToken>

Jika valid, user disimpan ke context Gin:

c.Set("user", user)
c.Next()

RBAC di route

Beberapa endpoint dilindungi langsung di router:

tasks.POST("", h.requireRole(domain.RoleProjectManager), h.createTask)
projects.DELETE("/:id", h.requireRole(domain.RoleProductOwner), h.deleteProject)
users.POST("", h.requireRole(domain.RoleAdmin), h.createUser)

RBAC di service

Service juga mengecek role untuk aturan bisnis penting:

if !HasRole(actor.Role, domain.RoleProjectManager) {
    return domain.Task{}, domain.NewError(domain.ErrForbidden, "Access denied. Insufficient permissions.")
}

Memiliki pengecekan di service penting karena service bisa dipanggil dari handler, test, command, worker, atau interface lain di masa depan. Aturan bisnis tidak boleh hanya hidup di HTTP middleware.

Refresh token rotation

Saat refresh token dipakai, token lama dicabut dan token baru disimpan. Ini mengurangi risiko jika refresh token lama bocor.

if err := s.store.RevokeRefreshToken(ctx, tokenHash); err != nil {
    return AuthResult{}, fmt.Errorf("revoking refresh token: %w", err)
}

Logout

Logout mengecek apakah refresh token milik user, lalu mencabut token tersebut. Jika refresh token kosong, logout dianggap selesai.

Inti keamanan: password tidak pernah disimpan sebagai plain text. Refresh token juga tidak disimpan mentah, tetapi dalam bentuk hash.
