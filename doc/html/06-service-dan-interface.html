Service dan Interface

Service adalah tempat business logic. Interface adalah kontrak yang membuat service tidak bergantung langsung ke database PostgreSQL.

Isi struct Service

type Service struct {
    store  Store
    tokens auth.TokenManager
    now    func() time.Time
}

store adalah dependency untuk data. tokens mengurus JWT. now disimpan sebagai function supaya test bisa mengontrol waktu jika diperlukan.

Constructor service

func New(store Store, tokens auth.TokenManager) *Service {
    return &Service{
        store:  store,
        tokens: tokens,
        now:    time.Now,
    }
}

Constructor menerima dependency dari luar. Ini membuat service eksplisit dan mudah dites.

Interface Store

Di Go, interface sebaiknya didefinisikan di tempat yang memakai interface itu. Project ini mengikuti pola tersebut: interface store ada di package service, bukan di package postgres.

type Store interface {
    UserStore
    RefreshTokenStore
    TeamStore
    ProjectStore
    ProjectTeamStore
    TaskStore
    TaskAssignmentStore
    CommentStore
    AttachmentStore
    NotificationStore
}

Store adalah interface gabungan. Ia menyusun interface kecil seperti UserStore, TaskStore, dan NotificationStore.

Contoh business logic

func (s *Service) CreateTask(ctx context.Context, actor domain.AuthUser, input TaskInput) (domain.Task, error) {
    if !HasRole(actor.Role, domain.RoleProjectManager) {
        return domain.Task{}, domain.NewError(domain.ErrForbidden, "Access denied. Insufficient permissions.")
    }
    if strings.TrimSpace(input.Title) == "" || len(input.Title) < 2 {
        return domain.Task{}, domain.NewError(domain.ErrValidation, "Task title must be at least 2 characters")
    }
    if input.Status == nil {
        status := domain.TaskStatusBacklog
        input.Status = &status
    }
    input.CreatorID = actor.ID
    return s.store.CreateTask(ctx, input)
}

Perhatikan pembagian tanggung jawab:

  • Service mengecek role.
  • Service memvalidasi title.
  • Service memberi default status.
  • Store menyimpan data.

Kenapa return struct kosong saat error?

Signature (domain.Task, error) mengikuti pola Go. Jika error tidak nil, pemanggil mengabaikan nilai pertama. Karena itu service mengembalikan domain.Task{} sebagai zero value.

Input type

Service punya tipe input sendiri, misalnya CreateUserInput, TaskInput, dan ProjectFilter. Ini mencegah handler langsung memakai model database sebagai input mentah.

Keuntungan interface untuk test

Karena service hanya butuh interface, test bisa membuat fake store tanpa PostgreSQL. Inilah alasan utama dependency inversion di project ini.

type fakeStore struct {
    createdTask domain.Task
}

func (f *fakeStore) CreateTask(ctx context.Context, input service.TaskInput) (domain.Task, error) {
    return f.createdTask, nil
}
Inti bab: service memegang aturan bisnis. Store memegang detail data. Interface menjadi batas kontrak di antara keduanya.
