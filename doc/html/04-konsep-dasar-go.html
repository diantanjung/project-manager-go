Bab 04

Konsep Dasar Go di Project Ini

Bab ini bukan teori kosong. Setiap konsep dijelaskan dengan contoh yang muncul di project: package, struct, pointer, interface, generic, error, context, dan method receiver.

Package

Setiap file Go dimulai dengan nama package. Package adalah unit organisasi kode.

package service

File di folder internal/service memakai package service. Package lain menggunakannya lewat import:

import "project-manager-go/internal/service"

Struct

Struct adalah kumpulan field. Contoh dari internal/config/config.go:

type Config struct {
    NodeEnv     string
    Port        int
    DatabaseURL string
    FrontendURL string
}

Struct cocok untuk model data, konfigurasi, request input, response, dan object service.

Tag struct

Di domain, field memiliki tag seperti json dan db:

type Task struct {
    ID          int    `json:"id" db:"id"`
    Title       string `json:"title" db:"title"`
    ProjectID   int    `json:"projectId" db:"project_id"`
}

json dipakai saat encode/decode HTTP JSON. db dipakai oleh sqlx untuk mapping kolom database ke field struct.

Pointer untuk nilai opsional

Beberapa field memakai pointer seperti *string dan *time.Time.

Description *string    `json:"description" db:"description"`
CreatedAt   *time.Time `json:"createdAt" db:"created_at"`

Artinya field bisa bernilai nil. Ini berguna untuk kolom database yang boleh NULL, atau input patch yang boleh dikirim sebagian.

Method receiver

Method adalah function yang menempel pada tipe. Contoh dari Service:

func (s *Service) CreateTask(ctx context.Context, actor domain.AuthUser, input TaskInput) (domain.Task, error) {
    // ...
}

(s *Service) berarti method ini milik pointer ke Service. Pointer receiver dipakai karena method memakai dependency di dalam service dan menghindari copy struct.

Interface

Interface menyatakan perilaku yang dibutuhkan, bukan implementasinya. Di internal/service/store_interfaces.go:

type TaskStore interface {
    CreateTask(ctx context.Context, input TaskInput) (domain.Task, error)
    ListTasks(ctx context.Context, user domain.AuthUser, filter TaskFilter) (domain.Paginated[domain.Task], error)
}

Service tidak peduli apakah data berasal dari PostgreSQL, memory fake, atau service lain. Selama tipe tersebut punya method yang cocok, ia memenuhi interface.

Generic

Generic memungkinkan tipe bekerja untuk banyak jenis data tanpa menghilangkan type safety.

type Paginated[T any] struct {
    Data       []T
    Pagination Pagination
}

T adalah placeholder tipe. Maka project bisa punya Paginated[domain.User], Paginated[domain.Project], dan Paginated[domain.Task].

Error

Go mengembalikan error sebagai nilai biasa. Contoh:

db, err := postgres.Open(ctx, cfg.DatabaseURL)
if err != nil {
    return err
}

Kalau ingin menambah konteks, project memakai wrapping:

return fmt.Errorf("saving refresh token: %w", err)

%w membuat error asli tetap bisa diperiksa dengan errors.Is.

Context

context.Context membawa sinyal cancel, timeout, dan metadata request. Handler mengambil context dari HTTP request lalu meneruskannya sampai database.

result, err := h.service.ListTasks(c.Request.Context(), currentUser(c), filter)

Slice dan map

Slice adalah list dinamis, misalnya []domain.TeamMember. Map adalah key-value, sering dipakai untuk whitelist nilai sort:

allowed := map[string]string{
    "createdAt": "created_at",
    "title":     "title",
}
Target setelah bab ini: kamu bisa membaca bentuk dasar kode Go di project ini dan tidak panik saat melihat pointer, interface, generic, atau error return.
