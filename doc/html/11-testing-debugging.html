Testing dan Debugging

Testing di Go sederhana: file test berada di sebelah kode dan diakhiri _test.go. Project ini punya test untuk auth, config, service, router, response, dan helper query.

Menjalankan semua test

go test ./...

Gunakan ini sebelum commit atau setelah mengubah behavior.

Menjalankan package tertentu

go test ./internal/service
go test ./internal/httpapi
go test ./internal/auth

Verbose mode

go test -v ./internal/service

-v menampilkan nama test dan log. Ini berguna saat ingin melihat test mana yang berjalan.

Menjalankan satu test

go test ./internal/service -run TestName

Ganti TestName dengan nama test. Jika lupa nama test, gunakan rg "func Test" internal/service.

Table-driven test

Pola umum di Go adalah table-driven test: satu test function, banyak skenario.

tests := []struct {
    name string
    input service.PageFilter
    want service.PageFilter
}{
    {name: "default page", input: service.PageFilter{}, want: service.PageFilter{Page: 1, Limit: 10}},
}

for _, tt := range tests {
    t.Run(tt.name, func(t *testing.T) {
        got := service.NormalizePage(tt.input)
        if got != tt.want {
            t.Fatalf("got %#v, want %#v", got, tt.want)
        }
    })
}

Fake store untuk service test

Karena service menerima interface store, test bisa memakai fake store. Ini menghindari database sungguhan untuk test business logic.

HTTP test

Router Gin bisa dites dengan httptest. Polanya: buat router, buat request, rekam response.

req := httptest.NewRequest(http.MethodGet, "/health", nil)
rec := httptest.NewRecorder()
router.ServeHTTP(rec, req)

Debugging runtime

Gejala Cara mulai debug
Server gagal start Cek DATABASE_URL, port, dan hasil go run ./cmd/db ping.
401 atau token invalid Cek format header Authorization: Bearer ... dan secret JWT.
403 forbidden Cek role user dan route yang memakai requireRole.
404 not found Cek apakah store mengubah sql.ErrNoRows menjadi domain.ErrNotFound.
List kosong Cek filter, pagination, dan access scope di helper projectWhere atau taskWhere.

Checklist sebelum mengubah fitur

  1. Pahami endpoint dan service method yang terdampak.
  2. Cek tipe input dan domain model.
  3. Cek interface store apakah perlu method baru.
  4. Tambahkan query di store PostgreSQL.
  5. Tambahkan atau update migrasi jika schema berubah.
  6. Tambahkan test pada layer yang berubah.
  7. Jalankan go test ./....
